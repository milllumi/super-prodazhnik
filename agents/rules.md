# Правила оформления и создания дизайна

Свод правил, адаптированный под «SUPER PROдажник» из трёх источников: Frontend Design Skill (Anthropic), Impeccable (Paul Bakaus, Apache 2.0) и Open Design (nexu-io, Apache 2.0). Пересказ и адаптация, не копия. Фирменный стиль (стекло на свечении, токены, оформления) от этого не меняется: правила помогают проектировать новое внутри него.

## 1. Режим экрана определяет смелость
| Режим | Что это у нас | Подход |
|---|---|---|
| Operate | сводки, таблицы, отчёты, настройки, калькуляторы | точность и сдержанность, знакомые паттерны, плотность и скорость чтения цифр |
| Read | новости обновлений, справка, журнал | читаемость: строка до 80 знаков, спокойный ритм |
| Persuade | вход, демо, презентация сайта | смелее: один запоминающийся элемент |
| Experience | обложки, обои, витрина | допустим эксперимент |
Почти весь сайт — Operate. Там смелость тратится в одном месте (герой), остальное тихое.

## 2. Процесс: план → сверка → сборка → самокритика
1. **Контекст.** Прочитай README, tokens.json, tables.md и компонент, ближайший к задаче. Реальный контент берём с сайта, не «lorem».
2. **Короткий план:** палитра (из токенов), типографика (роли), раскладка (одно предложение и ASCII-схема), принципы.
3. **Сверка плана с заданием.** Если часть плана — «как у всех» (одинаковые карточки, градиент, капс-метки), замени и скажи, что заменил и почему.
4. **Сборка** из компонентов системы. Новый элемент — только если готового нет.
5. **Самокритика по скриншотам** (агент `screenshot-loop`): светлая и тёмная, три оформления, 360 и 1100 px. Перед сдачей убери одно лишнее украшение.
Слово задания главнее любых правил: если пользователь закрепил цвет, шрифт или вид — делаем так.

## 3. Планка качества (обязательна всегда)
- Контраст текста ≥4.5:1 в обеих темах (крупный ≥3:1); видимый фокус; цель нажатия ≥44px; текст ≥12px (в шапке таблиц ≥10.5px).
- Адаптив: 360px без горизонтального скролла страницы; таблица скроллится внутри `.tbl`.
- `prefers-reduced-motion` отключает анимации; анимируем только `transform`, `opacity`, `filter`.
- Цвет не единственный носитель смысла: рядом число, знак или подпись.
- Состояния: загрузка, пусто, ошибка, длинный текст, большие числа, нет данных, нет прав.
- Цвета, радиусы, отступы — только из токенов. Своих #hex в компонентах нет.

## 4. Чего избегаем (типовые «приметы сгенерированного»)
- Одинаковые карточки с одним радиусом и одинаковой тенью на всё; градиент как украшение (у нас градиент только в герое).
- Заголовок с одним выделенным словом, подпись капсом над каждым блоком, метки «СЛОВО — фрагмент», стрелка «→» в каждой кнопке, номера 01/02/03 там, где нет последовательности.
- Fade-and-slide-up на каждой секции и hover-анимация на каждой карточке. Движение без действия человека — одно, редкое. Движение в ответ на действие (раскрыть, сохранить) — приветствуется.
- Моноширинный шрифт для всех мелких цифр (у нас `tabular-nums` в основном шрифте).
- Эмблемы-символы как украшение; декор без смысла. Структура (рамки, линии, подписи) должна нести информацию.
Исключение: если это прямо закреплено в нашей системе (капс в шапке таблиц, eyebrow над h2 карточки) — это наш стиль, а не примета.

## 5. Типографика
Одно семейство из токенов (`--font-sans`; в оформлении «Калькулятор» — Unbounded для заголовков и Manrope для текста). Шкала: 64 / 34 / 21 / 17 / 14 / 12.5 / 12. Цифры — `tabular-nums`, отрицательный трекинг только у крупных. Строка до 80 знаков. Заголовок — вес 650–700, не жирнее.

## 6. Цвет
База из токенов: `bg`, `card`, `text`, `muted`, `line`. Один акцент `blue`. Статусы `green`/`orange`/`pink` — только для статуса. Лайм — только в оформлении «Калькулятор». Свечение фона — три пятна по 11–16%; не добавлять четвёртое.

## 7. Раскладка
Выравнивание по левому краю, числа справа в таблицах, центр — только герой и тепловые карты. Сетка `auto-fit minmax(min(100%,310px),1fr)`, зазор 20px, отступ карточки 22px. Один герой на экран, один главный показатель.

## 8. Тексты интерфейса (русский)
- Простые слова, активный залог, регистр предложения; название действия одинаково на кнопке и в уведомлении: «Сохранить» → «Сохранено».
- Кнопка называет результат («Скачать отчёт»), не «Отправить».
- Ошибка объясняет, что случилось и что делать, без извинений и без «что-то пошло не так».
- Пусто — приглашение к действию («Выберите другой период»), не настроение.
- Названия показателей — как их называет сотрудник («Аксессуары», «Сим»), не как в системе.

## 9. Команды Impeccable → наши действия
| Команда | Что делаем у нас |
|---|---|
| shape | спланировать экран и показатель до кода |
| critique | оценка по эвристикам, баллы по 5 осям |
| audit | техпроверка: доступность, адаптив, производительность |
| polish | финальный проход перед сдачей |
| typeset, layout, colorize | поправить иерархию текста, отступы, цвет по токенам |
| animate | добавить осмысленное движение по теме оформления |
| clarify | переписать подписи, ошибки, пустые состояния |
| harden | состояния ошибок и пограничные случаи |
| distill | убрать лишнее |
| adapt | адаптация под 360px и планшет |
| document / extract | обновить DESIGN.md и токены из кода |
Подробно — в `agents/impeccable.md`.

## 10. Цикл Open Design
Задание → направление (выбрать оформление и режим) → дизайн-система (токены, компоненты) → артефакт (код/макет) → передача (файлы, Figma) → память (что подтвердили, в `DESIGN.md` и `memory.md`). Подробно — в `agents/open-design.md`.
