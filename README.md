# Сайт для продавцов и руководителей салонов — подключение (≈10 минут)

## Как выдаётся доступ
Всё берётся из вкладки **Доступ** вашей таблицы (A — роль, B — ФИО), отдельно ничего вносить не нужно:

| Роль в колонке A | Что видит сотрудник |
|---|---|
| новичок, ПТТ | личный кабинет продавца и общий рейтинг |
| РТТ, УТТ (также ТМ) | вид руководителя салона и калькулятор бонуса, без рейтинга и среднедневного бонуса |

- Кого нет в списке, не войдёт. Список можно менять в любой момент: права проверяются при каждом запросе, удалённый сотрудник теряет доступ сразу.
- Строки «Всего (…)» и «Итого» игнорируются.
- **Первый вход:** сотрудник вводит фамилию и имя, система предлагает придумать PIN из 4 цифр. PIN хранится только в виде хеша в свойствах скрипта, в таблице его нет.
- В колонке D скрипт сам пишет «PIN задан …», так видно, кто уже вошёл.
- **Сброс PIN** (забыл или кто-то занял чужую учётку): поставьте любой знак в колонке C напротив сотрудника. При следующем входе он задаст новый PIN, отметка очистится.
- 5 неверных PIN подряд блокируют вход этого сотрудника на 10 минут.

## Привязка салонов
- **РТТ / УТТ:** из таблицы «KPI ОСС текущий месяц» (ссылка берётся автоматически из вкладки «Ссылки»), лист «Сотрудники по салонам»: колонка A — ФИО менеджера, колонка B — магазин. Сейчас: Тюрин → КЗН Ершова 62 БЛН ТЦ Арт Центр, Ашрапова → КЗН Зорге 75 БЛН, Нигматулин → КЗН Ямашева 71а БЛН.
- **Продавцы:** если во вкладке «До сотрудника» нет ТТ, подставляется салон из того же листа KPI ОСС.
- Название салона там должно совпадать с названием в «Деталях продаж салоны». Если не совпадает, у руководителя будет подсказка, какое название не найдено.
- У скрипта должен быть доступ к таблице KPI ОСС (при первом запуске Google попросит разрешения).

## Подключение
1. Расширения → Apps Script → вставьте `Code.gs` → сохраните. Развернуть → Новое развертывание → «Веб-приложение»: выполнять от имени **Меня**, доступ **Все**. Скопируйте URL.
2. В `index.html` в строке `const API_URL = '';` вставьте URL. Загрузите `index.html` в репозиторий GitHub → Settings → Pages.

## Каждый месяц
Новая таблица: поменять `SPREADSHEET_ID` в `Code.gs` и обновить ссылку «Kpi ОСС текущий месяц» на вкладке «Ссылки». Затем Развернуть → Управление развертываниями → Изменить → Новая версия (ссылка на сайт не меняется). Вкладка «Доступ» должна быть и в новой таблице; PIN-коды сохранятся.

## Важно
- Первый, кто введёт имя коллеги до него, сможет задать PIN вместо него. Поэтому рассылайте ссылку всем сразу и смотрите колонку D; при подозрении ставьте сброс в колонке C.
- В рейтинг попадают только продавцы из списка «Доступ».
- Для калькулятора нужны CDN-библиотеки (Chart.js, html2canvas, jsPDF с cdnjs.cloudflare.com), на GitHub Pages они грузятся нормально.

## Обновление: рейтинг, графики, закрепление, общий свод, ссылки

- **Рейтинг и личные результаты** берутся из листа «До сотрудника ДЛ» (место — колонка «Место» перед ФИО, оценка — «Рейтинг»). Название листа — `CONFIG.SHEET_PLAN`.
- **Смены** (запланировано / прошло / осталось) считаются из листа «График»: отметки I, II, IV, V… в колонках дней, начиная с колонки J. Сегодняшняя дата берётся по часовому поясу таблицы.
- **Привязка ТМ / УТТ / РТТ к салонам** — из листа «закрепление» в KPI ОСС. Раскладка может быть любой: скрипт в каждой строке ищет ФИО руководителей из «Доступа» и названия салонов из «Деталей продаж салоны» (ФИО в объединённой ячейке тянется вниз; если в строке цепочка ТМ → УТТ → РТТ, салон закрепляется за всеми). Если такого листа нет, используется «Сотрудники по салонам».
- **«Общий свод»** (только РТТ и УТТ): лист показывается как есть — шапка и строки, где встречаются их салоны. Ищется сначала в этой книге, затем в KPI ОСС.
- **Ссылки** (вкладка «Ссылки» на сайте) видит и редактирует только ТМ; проверка роли выполняется на сервере. Формулы (значения с `=`, `+`, `-`, `@` в начале) не принимаются.
- ⚠ На момент настройки листов «закрепление» и «общий свод» в доступных книгах не было — после их создания всё подхватится само (кэш привязки — 10 минут). Если названия другие, поменяйте `KPI_BIND_SHEET` / `SHEET_SUMMARY` в `CONFIG`.
- После замены Code.gs: «Развернуть → Управление развертываниями → Изменить → Новая версия».

## Версия «SUPER PROдажник»: новости, бонус, общий свод

- **Новости** — кнопка-газета в шапке у всех сотрудников (красная точка — есть непрочитанное). ТМ публикует сам и модерирует: «Опубликовать / Отклонить / Удалить». Остальные нажимают «Предложить новость» — предложение уходит ТМ и появляется в ленте после одобрения (максимум 5 неодобренных предложений на человека). Хранится на листе «Новости» (создаётся автоматически; ТМ может править его и вручную). Права проверяются на сервере.
- **Бонус РТТ/УТТ**: калькулятор сам подставляет данные из таблицы: грейд (лист «Сопоставления» в KPI ОСС), часы, ATT, КВП по телефонам / аксессуарам+услугам / страховкам, выполнение плана по сим по салонам. Любое поле можно поменять руками. Поля, которые вы изменили, при обновлении данных больше не перезаписываются; кнопка «Подставить из таблицы» возвращает всё к данным таблицы.
- **Общий свод** показывает все направления листа (Сим, Телефоны, Аксессуары, Услуги, Страховки, Кредиты) со всеми колонками, в двух видах: «Таблица» (раскладка листа) и «По направлениям» (карточки для телефона). Показываются строки ваших салонов и строка с вашей фамилией.
- Ссылка на KPI ОСС берётся с листа «Ссылки»; поддерживаются и ссылка, и просто ID.
- Название сайта — SUPER PROдажник, новый логотип (молния на графике роста) добавлен на экран входа, в шапку и в иконку вкладки.

## Вид ТМ

Для роли «ТМ» (сейчас — Миллер Илья Андреевич) вкладка «Бонус» заменена на «Бонус ТМ» — это расчёт бонуса территориального менеджера (две страницы: «Выполнение» и «Аналитика», выгрузка в Excel).
Данные берутся из листов KPI ОСС «Экономические KPI», «я ЛИСТ» и «Операторские РДО ММБ»: скрипт отдаёт их только ТМ (проверка роли на сервере), а разбор и расчёт выполняет страница. Показатели подставляются сами, любое поле можно изменить вручную («из таблицы: …» возвращает исходное значение). ТМ также видит вкладку «Ссылки» и модерирует новости.

## Продавец → вкладка «Точка» (Результаты торговой точки)
- **Точка продавца:** где у него больше всего плановых часов в «Своде графика» (при равенстве — колонка «Торговая точка»).
- **План:** основная таблица, лист «План» (строка салона по колонке E). **Факт:** книга KPI ОСС — листы «Экономические KPI» и «Операторские таргеты» (нижние таблицы по ТТ, название в колонке H). Колонки заданы буквами в `RES_SPEC_` (Code.gs): при изменении структуры листов поправьте буквы.
- **Формулы шаблона** (остаток = план − факт; на день = остаток ÷ (дней до конца месяца + 1); вып.% = факт ÷ план; прогноз% = вып.% ÷ день месяца × дней в месяце) считает скрипт. «Страховки доля»: факт = страховки ÷ телефоны, план 9 %. «Сим итого»: факт = декада 1 + декада 2.
- Нет в источниках, поэтому строка не показывается или показан только факт: «Пленки», план «БП и Пакетные услуги», «Экстра Сим», «Аттачмент» (план 2 %, как в шаблоне). План «Кредитная заявка» — из KPI (в основном «Плане» его нет).
- Салон без факта в KPI ОСС (например, Максимова 2а БЛН) показывается с планом и пометкой.

## Калькулятор бонуса РТТ/УТТ: экономика и операторка из KPI ОСС

Сервер (`kpiPrefill_` в Code.gs) собирает для салонов руководителя прогнозы выполнения из книги KPI ОСС и отдаёт их в ответе `kpi`:

| Блок калькулятора | Источник | Колонка (ищется по заголовку) |
|---|---|---|
| Телефоны / Sell Out / Акс+Услуги / Страховки / Кредит·ККП / Комбо | «Экономические KPI» | `Прогн, %`, `Выполнение`, `Вып доли %`, `Выпол-е,%`, `Прогноз вып доли Комбо` (среднее, взвешенное планом салонов) |
| Аттачмент | «Экономические KPI» | `Аттачмент` |
| План по SIM | «Операторские РДО ММБ» | `Прогноз GI` (запасной — «Операторские таргеты», `Сим`) |
| Закрытие 1 / 2 декады | «Операторские таргеты» | `1 декада` / `2 декада`, прогноз |
| HB++ (доля > 25 %) | «Операторские таргеты» | `HB++`, доля |
| Выручка 1М, Актив 1–15 (Билайн) | «Операторские РДО ММБ» | `Выручка 1М`, `Gross AS 1-15`, % прогноз |

Поля, которые пользователь уже правил руками, не перезаписываются; кнопка «Подставить данные из таблицы» заполняет всё заново.

## Сотрудники ДЛ (вкладка ТМ)
План сотрудника на месяц, план на день (отставание), прогноз и место считаются на сайте (`dlModel_` в Code.gs), а не формулами листа «До сотрудника ДЛ».
- План на месяц = Σ по салонам (план салона на месяц из листа «План» ÷ часы всех сотрудников салона × часы сотрудника в салоне). Часы — «График» CB:CJ (Учитывается = 1). Покрыты все салоны, лимита в 10 колонок нет.
- ТТ — салон с максимумом часов. План на день = (план − факт) ÷ (плановые − отработанные смены, «График» AO/BZ). Прогноз = факт ÷ отработано × план смен ÷ план.
- Рейтинг = Σ мест по прогнозу (5 направлений) − аттачмент − число кредитов; место — по рейтингу.
- Исправлено относительно листа: сдвиг столбцов плана в VLOOKUP, #VALUE! при пустом факте, потеря Кукмора и Осиново, ручной список ТТ, `#REF!` в «Без ВМР».
После обновления: новая версия веб-приложения Apps Script и `installTrigger()`.

## Меню, «План на день», «Общий свод» (ноябрь)
- «План на день» (ТМ) считается на странице по механике «Итогов дня»: (план месяца − факт за прошлые дни) ÷ оставшиеся дни, включая выбранный; можно выбрать день, в том числе следующий.
- «Общий свод» выведен в том же формате, что «Итоги дня»: плитки по направлениям + таблица «Салоны × направления».
- «Сотрудники ДЛ»: копирование картинкой режет таблицу на три блока крупным шрифтом.
- Меню: порядок кнопок меняется перетаскиванием (на телефоне — долгим нажатием). На ПК меню — вертикальная панель, её можно двигать и свернуть в кнопку. Порядок, положение и сворачивание хранятся в браузере отдельно для каждого логина (`menuPref:<логин>`).

## Ноябрь, продолжение
- Продавцы (личный план, план на день, прогноз, место, рейтинг) читают ту же модель `dlModel_`, что и ТМ; лист «До сотрудника ДЛ» сайту больше не нужен. Листы «План на день» и «Свод графика» тоже не читаются. Сайт использует только исходные листы («Группа товаров», «График», «План», «Кредиты…», «Рабочее время сотрудников», «ВМР», «Показатели сотрудников», «Надстройка», …).
- Рейтинг: РТТ/УТТ/ТМ в нём не участвуют (места и рейтинг считаются среди остальных сотрудников).
- Единые пороги статусов: <85 % красный, 85–100 % жёлтый, ≥100 % зелёный (`ST_WARN`, `ST_OK`, `stCls`, `stCol`, `stVar`).
- Штуки без дробной части; строка «Данные обновлены…» на каждой вкладке.
- Вкладка «Аналитика» (РТТ/УТТ/ТМ): тепловая карта, темп по неделям; у ТМ ещё вклад сотрудников и SIM по тарифным группам.

## Разбор ВМР по ролям и уведомления

## Push-уведомления (OneSignal)
Тексты: 📋 сотруднику — «На тебя пришла анкета с результатом ✅/⚠️ N%»; 👥 РТТ/УТТ — «На твоего сотрудника … пришла анкета с результатом …»; 🚀 новость/обновление — «Скорее беги в приложение! Там новая штука появилась 👀».
Настройка (один раз):
1. onesignal.com → New App → Web; Site URL — адрес сайта на GitHub Pages; включите «Typical site»/свой Service Worker не нужен (используется `sw.js`).
2. В `index.html` задайте `const OS_APP_ID = '<App ID>';`.
3. Apps Script → Свойства скрипта: `ONESIGNAL_APP_ID`, `ONESIGNAL_API_KEY` (REST API Key), по желанию `SITE_URL` (ссылка, которую открывает push).
4. Каждый сотрудник один раз нажимает в колокольчике «🔔 Включить push». На iPhone сайт должен быть добавлен «На экран Домой» (iOS 16.4+). Получатель определяется внешним ID = ключ сотрудника (`external_id`).
Без шагов 2–3 работают уведомления внутри сайта (колокольчик).

## Салоны рядом: смежные салоны и трафик

В карточке «Салоны рядом» (РТТ/УТТ/ТМ) под таблицей по направлениям выводятся **смежные салоны** — те же адреса, но другого бренда (БЛН / МТС / МФ / Т2; «ТД» понимается как Т2). Сопоставление идёт по названию без бренда (например, «КЗН Кулахметова 28 … ТЦ Моки»).

Все значения читаются из листа «Экономические KPI» книги KPI ОСС (колонки ищутся по заголовкам: «Трафик», «Конв», «Прогн, %» и т. д.). После обновления Code.gs создайте новую версию развёртывания.

## Оклад и защита бонуса (v2026-12-10)
- Источник — лист «Надстройка»: салоны G:M (ставка города — H, ставки грейдов A/B/C — K:M), грейд сотрудника — O:R (имя в O, грейд в R).
- Оклад = отработанные часы (Факт 1С) × ставка города салона; прогноз оклада — плановые часы × ставка.
- Защита бонуса: бонус ÷ факт часов < ставки грейда сотрудника по его салону (салон с наибольшим числом часов) → бонус доводится до ставки × часы. Доплата сейчас = ставка × факт часов − бонус; на месяц — ставка × плановые часы − прогноз бонуса.
- Прогноз ЗП на месяц = оклад на плановые часы + прогноз бонуса с защитой. Если сотрудника или салона нет в «Надстройке», оклад и защита не считаются (прочерк).
- На сайте: карточка «Оклад и защита бонуса» (строки с защитой подсвечены), в сводке — оклад, бонус с защитой и прогноз ЗП. Работает и в «Бонусе команды».

- ТМ видит под каждой новостью «Прочитали: N» — имена, роли и время.
- Новости-«фишки» (автор «SUPER PROдажник») — фиолетовые с обводкой; новости от ТМ — стиль «Стиль» (шрифт берётся из выбранной темы).
## Гостевой доступ (24.11)
- Выданные на время разделы — отдельный блок меню «Предоставили доступ» (Отчёты, Итоги дня, Аналитика, Карточки, ВМР · доступ); собственные разделы роли открываются со своими данными. Карточки: `cards_get` принимает `own`.

## Комментарии к чекам без допов (24.11)
- В Attachment → «Чеки со смартфоном»: нажатие на название телефона открывает быстрый просмотр чека. К чеку без допов сотрудник/руководитель в зоне своего доступа пишет комментарий — один раз; ТМ подтверждает (`att_comment`, `att_confirm`), после подтверждения изменить нельзя. Лист «Комментарии аттачмент» создаётся автоматически; ТМ получает уведомление, автор — о подтверждении.

## Фокус и чеки (24.11)
- Проход дизайнера: блок «Фокус» в конце CSS (числа, плитки, итоги, выбранные фильтры, focus-visible). Чеки Attachment: время с минутами (`mi` в ответе, кэш `sales:rows2`). Рейтинг команды без процентов справа.

## Attachment: сортировка, недели, точка; вкладка ВМР

- **Сотрудники.** Таблица сортируется автоматически по аттачменту (шт/тел) от большего к меньшему. Если аттачмент ниже 1, вся строка заливается красным (цвет `--bad` темы сайта).
- **Недели.** Фильтр «Неделя» (пн–вс) в верхней панели и кнопки недель над списком «Чеки со смартфоном»; работает вместе с периодом и точкой.
- **Точка.** Кнопки выбора торговой точки в блоке «Проникновение по группам» (то же состояние, что и фильтр «Торговая точка»).
- **Меню.** Вместо вкладки «Прогноз» теперь «ВМР» (в группе «Итоги и темп», после «По дням»).

## Скорость новостей и ВМР

- **Новости.** Бэкенд держит ленту (2 мин, сбрасывается при любой правке) и список прочитавших (на месте обновляется при отметке) в кэше — больше не читает листы целиком на каждый запрос. Сайт делает один общий запрос ленты вместо трёх, показывает уже загруженное сразу и обновляет в фоне. В шлюзе новостей «Прочитано» срабатывает мгновенно, отметки уходят на сервер одной пачкой, «Продолжить» дожидается подтверждения.
- **ВМР, разбор.** «Динамика» и «Комбо и рассрочка» — отдельные блоки (карточки), а не вкладки внутри одной.
- **Меню.** Вкладка «Прогноз» вернулась, на телефоне она в «Ещё».
- **Видео в ВМР.** Ссылка на видео вынимается из ячейки надёжнее (в т. ч. если рядом с адресом есть текст).

## Защита бонуса по салонам (для ТМ)

«Сотрудники ДЛ» → «Бонус»: блок «Защита бонуса по салонам». По каждому салону — сколько сотрудников на защите, доплата на сегодня и **прогноз выплаты защиты на месяц** (ставка грейда × плановые часы − прогноз бонуса), плюс прогноз бонуса с защитой; внизу строка «Итого». Салоны отсортированы по сумме прогноза; при наведении на салон видно, у кого защита.

## Скорость загрузки (диагностика и что сделано)

**Диагностика.** Страница — один файл ≈1 МБ (≈370 КБ по сети со сжатием); почти половина по сети — логотипы презентации «Weekly Pulse» в base64 (167 КБ, не сжимаются), нужные раз в месяц. Разбор страницы в браузере — ≈0,1 с, узкое место — сеть и ответы Apps Script. Service Worker скачивал страницу заново при каждом открытии. Сервер на каждый опрос уведомлений (раз в 3 мин у каждого) читал лист и мог ждать фоновую «уборку».

**Фронтенд.**
- Логотипы вынесены в `wp-logo.json` (грузится только при сборке презентации): `index.html` стал на ≈160 КБ легче, по сети ≈240 КБ вместо ≈370 КБ.
- `sw.js` (v3): оболочка отдаётся из кэша сразу, свежая версия скачивается в фоне; если вышла новая — внизу баннер «Вышла новая версия сайта · Обновить».
- Новости запрашиваются параллельно с данными, один общий запрос вместо трёх; «Прочитано» — мгновенно.
- Фоновая уборка сервера вызывается отдельным запросом `maint` (без ожидания).

**Бэкенд (`Code.gs`).**
- Уведомления: последние 400 строк в кэше на минуту (сбрасывается при новом уведомлении); `maintain_` вынесен из `notif_list` в `maint`.
- Новости (лента и «кто прочитал»), комментарии к чекам и ссылка на KPI ОСС — в кэше с точным сбросом при правках.

**Файлы для GitHub:** `index.html`, `sw.js`, `wp-logo.json` (новый), `Code.gs`, `README.md`.

## Дизайн-аудит, Attachment, «Факт продаж»

- **Аудит читаемости** (по DESIGN.md: контраст ≥4.5:1, текст ≥12px) на всех вкладках, в светлой/тёмной темах и в оформлениях iOS 27 / iOS 16 / Pixel / «Стиль» (узкий экран 390 px и десктоп): горизонтальной прокрутки, обрезанного и вылезающего за карточку текста не найдено. Исправлено: приглушённый текст `--muted` в светлой теме потемнел (3,6 → 4,9:1), подписи 10–11 px подняты до 12 px, цвета «+/−» и «не продано» в светлой теме темнее, кнопка копирования не наезжает на заголовок карточки.
- **Attachment, цвет шт/тел:** меньше 2,5 — красный; от 2,5 до 3,2 — без цвета; больше 3,2 — зелёный (дерево «По привязке», карточки, таблица «Сотрудники»). Строка сотрудника с аттачментом ниже 1 по-прежнему красная.
- **Итоги дня → Факт продаж:** снова читаемая таблица «Салоны × направления» (план / факт / %) вместо карточек; общий код таблицы вынесен в `drTableHtml`.

## Темы и анимации
В панели «Оформление» остались только пресеты (Классика, Океан, Закат, Лес, Лаванда, Роза, Графит, iOS 16, Pixel, Стиль). У всех, кроме «Классики», свой характер движения (волна, свечение, рост, размытие, «поп», сдвиг) и плавающий фон; «Стиль» — яркие карточки-«стикеры», лаймовые метки и анимированный фон. Уважается `prefers-reduced-motion`.
Attachment: продавец без доступа ТМ/РТТ/УТТ видит только свои чеки (фильтр и на сервере, и на клиенте).

**Агент `data-refresh`** (`agents/data-refresh.md`): обновление данных на сайте — новая выгрузка/месяц, `warmCache()`, новая версия развёртывания, сверка «последнего чека» и ключевых чисел с таблицами.

## Логотип, презентация, ручной Excel
- Логотип с надписью — только в шапке сайта и на экране входа; в презентации (титул и колонтитулы слайдов) используется знак без надписи (`wp-logo.json`, ключ `m`), подпись «SUPER PROдажник» из колонтитула убрана.
- Презентация «Собрание с управленцами» / Weekly Pulse: вместо «светлая/тёмная» выбирается пресет темы (Классика, Океан, Закат, … Стиль); акцентные цвета слайдов берутся из пресета.
- «Отчёты»: у ТМ и в демо-режиме есть кнопка «📎 Загрузить Excel» — файл (.xlsx/.xls/.csv) разбирается в браузере и показывается вместо данных сайта в выбранном отчёте; «Вернуть данные сайта» отменяет. Данные не сохраняются и никуда не отправляются.

## Обновление (ПК, «Стиль», презентация)
- ПК: шапка и баннер идут на всю ширину, меню прикреплено к шапке слева (`menu-attached`) — общий край, нет «обрыва» в левом верхнем углу; позиция меню следует за шапкой при прокрутке.
- «Стиль»: фон — точки по диагонали, разбегающиеся от курсора (как в артефакте «Бонус-калькулятор»), canvas `#bkDots`, цвет `--bk-dot`; при `prefers-reduced-motion` точки не движутся.
- «Презентация в новом дизайне»: выбор темы-пресета сверху карточки; цвета слайдов (акцент, второй цвет, статусы, фон) берутся из пресета. «Краткая презентация недели» убрана.
